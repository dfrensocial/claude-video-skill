# Dfren Video Editing SOP (read this first, every job)

Applies to every edit job, for any fresh Claude Code session. Order: **read this file -> read the job inputs -> load memory (knowledge graph) -> run the flow below.**

## 0. Non-negotiables
1. **DaVinci Resolve Studio is mandatory.** Everything generated by code (typography, fire/transition clips, flashes, glitches, sound stems, grade, zooms, titles) must end up as clips/settings on an **editable Resolve timeline**, and the **delivered file is rendered by Resolve** (`resolve_job.py render`). ffmpeg/HyperFrames may *make assets* and *previews*, never the final file. Code-only output is not acceptable.
2. **Never modify the user's files.** Inputs are copied (read-only) into the job; originals stay untouched.
3. **The process lives here; media lives in job folders.** This SOP and tooling hold no media.
4. Motion graphics/text follow the **reference video** and the user's idea text. Not generic.
5. Verify every Resolve write (the scripts read back counts; check `output/timeline_report.json` `problems` is empty and `timeline_frames == expected_frames`).
6. Be honest about what could not be verified. Report limits (below).

## 1. Start-of-job ritual (fresh session)
1. Read this SOP, then `E:\video editor claude\CLAUDE.md` (engine notes: Windows, `python`, `py -3.13` fallback, CUDA).
2. Make sure Resolve **Studio** is running (start `C:\Program Files\Blackmagic Design\DaVinci Resolve\Resolve.exe` if not; Preferences > System > General > External scripting = Local). Quick check: `python scripts/preflight.py`.
3. Memory: `python scripts/kb.py context --client <client> --style <style>` (rules, past outcomes). Obey scoped rules (job > client > style > global).

Scripts live in `E:\video editor claude\.claude\skills\resolve-editor\scripts\` (below: `S/`).

## 2. Input contract (what the user gives per job)
- (a) raw video file(s), (b) type of edit, (c) **exactly one** reference video, (d) a text description of the idea/transition.
Missing or more than one reference -> ask. Everything else is derived.

## 3. Step 1 - Intake (organises the inputs; the Desktop hub)
`python S/intake.py --raw FILE... --reference FILE --type "..." --idea "..." --name SLUG [--client X --lang tanglish|en --placement organic|paid]`
Creates `Desktop\Dfren Video Editor\jobs\<date>_<slug>\` with `inputs/` (read-only copies, `brief.md`, `manifest.json`), `analysis/` (contact sheets, transcript, speech window, colour, reference fingerprint, `memory.md`, `style_brief.md` skeleton), `work/`, `output/`.

## 4. Step 2 - Understand (do not skip; this is what makes it look like the reference)
- View the contact sheets and the transcript; read `reference_fingerprint.json` (cuts/s, text bursts, palette, wpm, nearest styles).
- Fill in `analysis/style_brief.md`: how the reference's text enters/exits, type scale and weights, colours, camera moves, transition types, sound hits, pacing; map each to what we will do on the user's footage. Include the user's idea text verbatim.
- Transcript quality: trust only `reliable` ranges (see Tanglish notes in engine CLAUDE.md); ask for script if unreliable.

## 5. Step 3 - Creative plan
Write `work/creative_plan.json` (template: `.claude/skills/resolve-editor/examples/fire-reel_build_edit.py` and the sample `jobs/.../work/creative_plan.json`). Keys: `job, client, size, fps, duration, sources{id:path}, clips[{src,in,out,mute}], base_zoom, punches[{t,zoom}], shakes, grade{cdl,lut}, grade_changes, voice{target_lufs,chain}, cutaways, transitions[{kind: fire_wipe|lick|flash|glitch,t,dur}], typography{events}, native_titles[{t,dur,text,font,size,color,pos_px}], sound{drone,events[{t,kind,gain_db}]}, markers`. Pin events to **word times** from the transcript. Dense, designed, per-video colours (palette.py) - no fixed brand colour.

## 6. Step 4 - Generate assets
`python S/make_assets.py JOB [--only voice,transitions,typography,sound] [--force]` -> `work/assets/` + `manifest.json`: cleaned-voice copy of the raw (video untouched), per-event typography clips (one clip each, auto-laned), fire/flash/glitch clips, one WAV per sound event, loudness-calibrated. File names carry content hashes so Resolve never reuses a stale asset.

## 7. Step 5 - Build in Resolve
`python S/resolve_job.py build JOB --version v1` (project `Dfren - <job>`, timeline `<job> v1`; a new version = new timeline, never overwrite).
Track map: **V1** A-roll sub-clips with native stepped zoom/pan/tilt + CDL/LUT; **V2..** native editable Title clips; above them cutaways -> glitch -> typography -> fire/flash -> HUD (each its own clip, named and colour-coded); **A1** voice, **A2..** drone + one clip per sound event; markers on key beats.
Then `render`, `export`, `review` (or `all`). Outputs in `output/`: `<client>_<job>_<ratio>_<WxH>_<version>.mp4` (from Resolve), `<job>.drp` (full Resolve project), `review_sheet.jpg`, `qc.json`, `timeline_report.json`.

## 8. Step 6 - Review loop
View `review_sheet.jpg` and full-res frames at key beats; fix text overlap/clipping, safe zones (organic y150-1520, x<=920), pacing, loudness (-14 LUFS +/-1.5, true peak <= -1 dBFS). Change the plan -> `make_assets` -> `build --version v2` -> render. Max 3 rounds before reporting. QC must have no FAIL.

## 9. Step 7 - Learning
Record user feedback and outcomes: `python S/kb.py feedback "..." --scope global|client|style|job`, `kb.py outcome ...`. Add new machine facts to engine `CLAUDE.md`. Commit tooling changes (never media, never third-party packs; repo is public).

## 10. Final report format
Output path(s) (mp4 + .drp), what is editable in Resolve and where (track map), QC result, what was NOT verified, assumptions, questions.

## 11. Honest limits (state them to the user)
- Motion *inside* typography/fire/glitch clips is baked video (each is a separate movable/trimmable clip). Static titles are real Resolve Text titles; **keyframed title animation is not imported by Resolve's FCPXML path.**
- Audio gain is not scriptable: stems are pre-gained at asset time; fine mix tweaks are done in Resolve by the user.
- The final render comes from Resolve H.264; if a Resolve render fails, fix it - do not substitute an ffmpeg render.

## 12. Troubleshooting
- Resolve "did not answer": start Resolve Studio, enable external scripting; scripts auto-retry with `py -3.13`.
- Missing/stale media in a render: re-run `make_assets` (names are hashed) then build a new version.
- Timeline longer than plan: overlays are clamped; check `timeline_report.json`.
