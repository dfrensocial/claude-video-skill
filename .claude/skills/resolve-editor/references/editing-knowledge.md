Rules: every claim has a link. UNVERIFIED = only a weak/secondary source or none. Search tools returned thin results on craft numbers; where no source exists the number is labelled as a starting point to test, not a fact. Prefer measured results on this machine (CLAUDE.md) over anything here.

## 1. Meta / Instagram Reels ad creative

**Hook and retention**
- Meta names three Reels hook types: value-promise (lead with the benefit), statement-of-intent (say what they will see/learn), question/invitation. Meta says to A/B test hooks and iterate fast because small hook changes can matter a lot. [Social Media Today, relaying Meta's blog](https://socialmediatoday.com/news/meta-shares-tips-on-reels-hooks-creative-diversification-in-ads-and-threa/808182)
- Meta reports adding music or voiceover to Reels was linked to up to 13% higher incremental conversions (Meta-claimed, via same article). [source](https://socialmediatoday.com/news/meta-shares-tips-on-reels-hooks-creative-diversification-in-ads-and-threa/808182)
- Meta: 9:16 video with audio cut cost per result 34.5% vs image ads in its test; key messages inside the safe zone perform better; Reels default to sound on, so plan audio. [Meta Reels ads page](https://www.facebook.com/business/ads/facebook-instagram-reels-ads)
- Meta says broad creative diversification (many variants) helps its delivery system match ads to people. Practical use: deliver 2-3 hook variants per cut (see gaps). [source](https://socialmediatoday.com/news/meta-shares-tips-on-reels-hooks-creative-diversification-in-ads-and-threa/808182)
- Tactics repeated by agencies (not Meta primary): open on motion, a tight face, an unexpected visual or a direct claim about the viewer's situation; keep on-screen value text to ~5 words; hold the logo reveal until ~3 s in. UNVERIFIED as performance rules. [Tiger Pistol](https://tigerpistol.com/vertical-video-ad-best-practices/), [summary of search](https://www.straightnorth.com/blog/meta-ads-creative-best-practices-that-convert/)
- The widely quoted "47% of value in first 3 s" is UNVERIFIED (no primary Meta source found). Do not cite it to clients.

**Safe zones**
- Meta's own image-ad spec for Reels: leave about 14% top, 35% bottom and 6% each side free of text/logos/key elements. [Meta image spec, Instagram Reels](https://www.facebook.com/business/ads-guide/update/image/instagram-reels)
- A video-specific percentage was not retrievable (Meta help article 980593475366490 body not returned). Meta provides a safe-zone checker template. [Meta help](https://www.facebook.com/business/help/980593475366490/), [Reels ads page](https://www.facebook.com/business/ads/facebook-instagram-reels-ads)
- DISCREPANCY with `platforms.md`: studio overlay gives safe text box y 150-1520 on 1920 (bottom ~21% blocked, top ~8%). Meta's 14/35/6 rule on 1080x1920 gives x 65-1015, y 269-1248. Recommendation: keep captions/hook text inside the stricter Meta box (y 270-1250) for paid placements, use the studio box only for organic Reels. Re-measure overlay if Meta UI changed.

**Specs (third-party aggregators; Meta's video spec page was not retrievable, treat as UNVERIFIED and test-upload)**
- 9:16, MP4/MOV, H.264 + AAC, 1080x1920 (some list 1440x2560), 30 fps, stereo AAC from 128 kbps, file up to 4 GB; no licensed music, GIFs or face effects in Reels ads. [Moda summary of specs](https://moda.app/resources/sizes/meta-reels-ad), [Superscale](https://superscale.ai/learn/meta-ad-sizes)
- Length: ceilings quoted vary (90 s common, up to 15 min listed); performance guidance repeated by vendors is 15-30 s. Meta itself gave no duration on the Reels page. [AdStellar](https://www.adstellar.ai/blog/video-ad-length-best-practices), [Meta page](https://www.facebook.com/business/ads/facebook-instagram-reels-ads)
- No official bitrate was found. Keep current delivery (H.264 High, yuv420p) and add an explicit video bitrate target (see gaps; value is a choice, UNVERIFIED as Meta requirement).

**Sound-off and CTA**
- Design so the message survives muted: burned-in captions + on-screen key text. [Tiger Pistol](https://tigerpistol.com/vertical-video-ad-best-practices/) (agency guidance)
- CTA: Meta says place the hook and CTA inside the safe zone. [Meta dev blog on Reels ads](https://developers.facebook.com/blog/post/2024/11/07/unlock-the-power-of-reel-ads/) (general statement; no timing rule found, so "verbal CTA in last 3-5 s + end card" is house style, UNVERIFIED).

## 2. Editing craft

- J-cut = next scene's audio leads the picture; L-cut = previous audio continues over the new picture. Room tone / ambience under the join makes either work; crossfades are a patch for mismatched room tone and can cause doubled speech or phase issues if overused. [Vimeo](https://vimeo.com/blog/post/j-cuts-l-cuts), [Epidemic Sound](https://www.epidemicsound.com/blog/j-cuts-and-l-cuts/), [CapCut guide](https://www.capcut.com/create/j-cuts-and-l-cuts-dialogue-edits)
- Starting overlap for J/L cuts of 3-12 frames is from one weak source: UNVERIFIED, tune by waveform/ear. [CapCut guide](https://www.capcut.com/create/j-cuts-and-l-cuts-dialogue-edits)
- Jump cuts: acceptable in ads; a J-cut or continuous room tone under a jump cut helps the viewer follow. Record 10-30 s of room tone at the shoot (or lift a silent region from the take) and lay it under every cut so silence gaps are never digital zero. [Vimeo](https://vimeo.com/blog/post/j-cuts-l-cuts) (room-tone principle); duration is common practice, UNVERIFIED.
- Reading speed: Netflix English guide is 20 characters/s for adult programmes (17 for children's), 42 chars/line, max 2 lines (per tool page quoting the guide); BBC works at 160-180 words/min, i.e. about 2.7-3 words/s (arithmetic mine). Existing skill rule "hold = words/3 + 0.4 s" is consistent with this. For short-form kinetic captions, 1-3 words per card is faster than these subtitle norms and is a style choice. [Subtitle reading-speed tool](https://www.bookwriter.vip/subtitle-reading-speed-checker), [ProZ thread](https://hun.proz.com/forum/subtitling/369973-style_guide_of_subtitling.html). Verify against the current Netflix timed-text guide before quoting.
- Loudness: sources conflict. One table gives Reels -14 LUFS / -1 dBTP (practical start, not official); another claims Instagram -10 to -12 LUFS. No official Meta figure found. Keep -14 LUFS integrated and -1 to -1.5 dBTP; test-upload and measure what comes back. [OpenClip](https://openclip.app/learn/loudness-standard), [Film & Flow](https://filmandflow.beehiiv.com/p/the-ultimate-lufs-guide-perfect-audio-for-social-media)
- Ducking depth: no source found for "-15 to -20 dB". Treat music-under-voice as a mix choice: verify with a short-term loudness measurement (voice region vs music-only region) and phone-speaker check. UNVERIFIED number.
- Punch-in rhythm, B-roll cover cadence (2-4 s) and beat-synced cuts: no authoritative source found; existing skill values stay as house style. For beat sync use `hyperframes beats` (HyperFrames CLI lists a `beats` command) or librosa beat tracking to snap cuts to the nearest beat within ~2 frames. [HyperFrames CLI skill listing in this workspace] UNVERIFIED effect on performance.
- Motion easing norms (ease-out in, ease-in out, no linear) are already in motion-and-text.md; no new sourced numbers found.

## 3. Colour

**Workflow (single synthesis from guides; order is debated, so keep it fixed per house style)**
1. Fix the colour path first (input colour space / conversion), then exposure and white balance on the whole shot, then contrast/saturation, then a separate skin node only if global fixes fail; within the skin node fix hue before saturation. [DaVinci Resolve Club, skin tone correction](https://davinciresolveclub.com/skin-tone-correction-davinci-resolve/)
- Skin-tone line: enable Show Skin Tone Indicator in the vectorscope; sample a power-window on forehead/cheek; neutrally lit skin should sit on the line. It is a hue reference only, not a brightness/saturation target. [Frame.io skin tones](https://blog.frame.io/2020/10/05/skin-tones-in-davinci-resolve/), [Resolve Club](https://davinciresolveclub.com/skin-tone-correction-davinci-resolve/)
- Offset-wheel "push skin to the line" tricks move the whole image; check against the rest of the shot. [4kshooters](https://4kshooters.net/2016/12/15/how-to-get-pleasing-natural-looking-skin-tones-in-davinci-resolve-12-5-in-two-easy-steps)
- Coloured gel lighting: no sourced procedure found (UNVERIFIED). House rule suggestion: do NOT neutralise an intentional gel look; white-balance on skin/neutral prop only to a believable level, protect the gel colour with a qualifier-based skin node, and judge by skin line distance. Flag to user if gel colour fights brand palette.
- Scene matching B-roll: match on waveform/vectorscope averages first (already in `color_match.py`), reject clips that need heavy correction.

**LUT order**
- Technical LUT (log or colour-space to Rec.709) first; corrections next; creative look LUT last on its own node; if Resolve colour management already maps the camera to Rec.709, do not add a camera conversion LUT (double conversion). Check whether the phone is actually shooting log; SDR needs no conversion LUT. [Resolve Club LUT guide](https://davinciresolveclub.com/how-to-use-luts-in-davinci-resolve/), [Resolve Club RCM/CST](https://davinciresolveclub.com/davinci-resolve-color-management-rcm-cst/)
- LUT strength: put the look on its own node and lower that node's Key Output Gain. A "50-80% start" figure is from a LUT seller, UNVERIFIED. [Resolve Club LUT guide](https://davinciresolveclub.com/how-to-use-luts-in-davinci-resolve/)

**Scripting API (from the Resolve README text, mirrored at X-Raym's gist)**
- `Graph.SetLUT(nodeIndex, lutPath)`: nodeIndex 1-based since 16.2.0; LUT must already be discovered, call `Project.RefreshLUTList()` after copying the file into the LUT folder. [README mirror](https://gist.github.com/X-Raym/2f2bf453fc481b9cca624d7ca0e19de8)
- `TimelineItem.SetCDL({"NodeIndex":"1","Slope":"r g b","Offset":"r g b","Power":"r g b","Saturation":"s"})`: values are strings, NodeIndex 1-based. [README mirror](https://gist.github.com/X-Raym/2f2bf453fc481b9cca624d7ca0e19de8)
- `Graph.ApplyGradeFromDRX(path, gradeMode)`: 0 no keyframes, 1 source-timecode aligned, 2 start-frames aligned. [README mirror](https://gist.github.com/X-Raym/2f2bf453fc481b9cca624d7ca0e19de8)
- `TimelineItem.ExportLUT(exportType, path)`: `resolve.EXPORT_LUT_17PTCUBE / 33PTCUBE / 65PTCUBE / PANASONICVLUT`. [README mirror](https://gist.github.com/X-Raym/2f2bf453fc481b9cca624d7ca0e19de8)
- Gotcha: `TimelineItem.CopyGrades` replaces the target's grade wholesale and creates no version (per davinci-resolve-mcp docs). [davinci-resolve-mcp](https://github.com/samuelgursky/davinci-resolve-mcp)

[Digital Production](https://digitalproduction.com/2026/09/08/resolve-21-1-adds-mcp-and-finally-gets-presets/), [CineD](https://www.cined.com/es/davinci-resolve-21-1-released-ai-assistant-integration-via-mcp-individual-hdr-trims-and-python-scripting-moves-to-studio/)

[Digital Production](https://digitalproduction.com/2026/09/08/resolve-21-1-adds-mcp-and-finally-gets-presets/), [CineD](https://www.cined.com/es/davinci-resolve-21-1-released-ai-assistant-integration-via-mcp-individual-hdr-trims-and-python-scripting-moves-to-studio/), [Cutsio guide](https://cutsio.com/blog/how-to-connect-ai-assistant-davinci-resolve-21-1-mcp)

**AppendToTimeline and frames**
- Signature: `MediaPool.AppendToTimeline([{clipInfo}])`; clipInfo keys `mediaPoolItem, startFrame, endFrame`, optional `mediaType` (1 video only, 2 audio only), `trackIndex`, `recordFrame`. [README mirror](https://gist.github.com/X-Raym/2f2bf453fc481b9cca624d7ca0e19de8)
- endFrame: secondary sources say INCLUSIVE (`endFrame:23` gives 24 frames), while some forum/skill examples use `endFrame:25` for "first 25 frames" (exclusive). Contradictory, so keep the existing live `verify` test and record outcome. Timeline `GetEndFrame()` is exclusive (600-frame timeline reads back 601 if you add +1; measured on Studio 19.1.3.7 by a third party). [DeepWiki Resolve API](https://deepwiki.com/deric/DaVinciResolve-API-Docs/3.2.1-timeline-creation-and-manipulation-(python)), [davinci-resolve-mcp PR 269](https://github.com/samuelgursky/davinci-resolve-mcp/pull/269), [Blackmagic forum](https://forum.blackmagicdesign.com/viewtopic.php?p=906161)
- Use integer frames: fractional startFrame/endFrame/recordFrame makes AppendToTimeline silently return nil/empty. Always check the return list length. [auto-subs issue 745](https://github.com/tmoroney/auto-subs/issues/745)
- recordFrame: one forum post reports 90000 = 01:00:00:00 on a 25p timeline, i.e. timeline start timecode offset applies. Compute recordFrame from timeline start frame, not 0. UNVERIFIED across versions. [Blackmagic forum](https://forum.blackmagicdesign.com/viewtopic.php?p=906161)

**Titles / Text+**
- `Timeline.InsertFusionTitleIntoTimeline(titleName)` and `InsertTitleIntoTimeline(titleName)` return a TimelineItem; the title name must match the Effects Library name (e.g. "Text+"). [README mirror](https://gist.github.com/X-Raym/2f2bf453fc481b9cca624d7ca0e19de8)
- Setting text: `item.GetFusionCompByIndex(1)`, find the Text+ tool (`comp.GetToolList(False,"TextPlus")`), set input `StyledText` (untested sketch from a forum post; Python list index is 0-based). Test in the Console first. [Blackmagic forum](https://forum.blackmagicdesign.com/viewtopic.php?p=1156041)
- Fusion comp API: `TimelineItem.AddFusionComp / ImportFusionComp(path) / ExportFusionComp / LoadFusionCompByName / DeleteFusionCompByName`. A `.setting`/`.comp` import is the reliable way to carry animation. [README mirror](https://gist.github.com/X-Raym/2f2bf453fc481b9cca624d7ca0e19de8)

**Subtitles**

Fallbacks: build Text+ per caption (TextPlus2SRT project does the inverse), or burn captions with ffmpeg/HyperFrames. UNVERIFIED that a script-only SRT import is impossible; test `MediaPool.ImportMedia([srt])` once. [editingtools guide](https://editingtools.io/guides/convert-srt-to-resolve-subtitle), [Resolve_TextPlus2SRT](https://github.com/david-ca6/Resolve_TextPlus2SRT)

**Render queue**

## 5. Tamil / Tanglish ASR

- faster-whisper repetition loops: set `condition_on_previous_text=False`, `vad_filter=True`; for residual hallucinations in silence use `word_timestamps=True` with `hallucination_silence_threshold`. VAD `min_silence_duration_ms` default is disputed (140 vs 2000 across sources/versions): read it from the installed package. [LocalAIMaster](https://localaimaster.com/blog/whisper-hallucination-fix), [faster-whisper issue 843](https://redirect.github.com/SYSTRAN/faster-whisper/issues/843), [pyvideotrans VAD](https://pyvideotrans.com/en/vad) (commercial/anecdotal sources). This matches the looping seen on this machine with `small`+auto, so add these flags.
- Always set `language="ta"` explicitly for Tamil-dominant audio (no source measured effect; consistent with local finding that auto flips).
- `initial_prompt` for Tamil/Tanglish: no source found. Treat a prompt of a few expected brand/product words (in the script's script) as an experiment; UNVERIFIED. Whisper writes Tamil in Tamil script, so a romanised prompt is unlikely to yield romanised output.
- Tamil fine-tunes: `vasista22/whisper-tamil-medium` is Apache-2.0, self-reported WER 6.5 (Common Voice 11) / 6.97 (FLEURS); model card shows Transformers usage only, so use it via `ctranslate2` conversion (`ct2-transformers-converter`) for faster-whisper. [HF model card](https://huggingface.co/vasista22/whisper-tamil-medium) A CT2 Tamil build `ukta-app/whisper-tamil-ct2` exists (licence not checked). [HF](https://huggingface.co/ukta-app/whisper-tamil-ct2) Benchmarks are clean read-speech, expect worse on noisy Tanglish.
- A separate Tamil fine-tune card claims 25.27% WER on FLEURS-Tamil vs 48.58% for large-v3 (self-reported). That is a useful hint that stock large-v3 is poor on Tamil. [HF osmapi/tamil-asr-qwen3](https://huggingface.co/osmapi/tamil-asr-qwen3)
- AI4Bharat IndicWhisper (Vistaar): fine-tuned Whisper for 12 Indian languages, datasets/code/models open-sourced; licence not stated in the pages found (a blog says mostly Apache 2.0, UNVERIFIED). Check the repo/model card before commercial use. [Vistaar repo](https://github.com/AI4Bharat/vistaar), [AI4Bharat ASR](https://ai4bharat.iitm.ac.in/areas/asr)
- Sarvam API (hosted, paid): speech-to-text Rs 30/hour (Rs 45 with diarization), billed per second, new users get Rs 100 credit. Model `saaras:v3` supports 23 languages with output `mode` = transcribe / translate / verbatim / translit (Latin script) / codemix; REST up to 30 s, batch up to 1-2 h per file (docs disagree). `translit` is the closest documented route to romanised Tanglish, but examples are Hindi only, so test Tamil. [Sarvam pricing](https://docs.sarvam.ai/api-reference-docs/pricing), [Saaras model page](https://docs.sarvam.ai/api/getting-started/models/saaras), [output modes](https://docs.sarvam.ai/api/api-guides-tutorials/speech-to-text/how-to/select-output-mode.md). Needs sending client audio to a third party: ask first.
- Google Chirp 3: Tamil support and pricing NOT confirmed (Tamil not visible in the launch list I saw). Skip unless user asks. [Google docs](https://docs.cloud.google.com/speech-to-text/docs/models/chirp-3)
- Romanising Tamil script (local, free): Aksharamukha (`pip install aksharamukha`) has romanisation schemes including "Roman (Colloquial)"; AI4Bharat IndicXlit native-to-Roman support differs by version (check). Tamil has no standard romanisation, so output spelling needs a house style, and English words inside Tamil sentences stay as the ASR wrote them (script `ta` text will contain Tamil-script English loanwords, not Latin). Pipeline: Tamil-script ASR -> Aksharamukha colloquial -> human glance. [Aksharamukha](https://pypi.org/project/aksharamukha/), [IndicXlit](https://pypi.org/project/ai4bharat-transliteration/), [Tanglish](https://en.wikipedia.org/wiki/Tanglish)

## 6. Memory / knowledge graph for the editing agent

Design (synthesis of the cited prior art; the combination itself has no single reference):
- Store facts as nodes (preference, rule, client, technique, asset, outcome) and typed weighted edges in one `memory/graph.json` (atomic write via temp file + rename; one writer). Keep it tiny: cap edges per node and prune below a minimum weight. [Hindsight](https://arxiv.org/pdf/2512.12818), [AtomMem](https://arxiv.org/pdf/2606.19847)
- Retrieval score = recency x importance x relevance. Generative Agents uses exponential recency decay (factor 0.995 per hour in their sandbox), LLM-rated importance 1-10, and embedding relevance; implementation weights seen in secondary sources are unverified. For us relevance = tag overlap (client, ad type, step) instead of embeddings. [Generative Agents](https://arxiv.org/pdf/2304.03442)
- Decay per node kind: identity/brand rules slow or none, operational tips fast; user-locked rules never decay; archive instead of delete. [Ori memory](https://socket.dev/npm/package/ori-memory/overview/0.5.0), [Ebb MCP](https://images.glama.ai/mcp/servers/jochemverheul/ebb-mcp), [adaptive decay paper](https://arxiv.org/pdf/2604.26970)
- Feedback to rules: log each user correction as an episode (what the agent did, what user said, client, step); after 2-3 repeats, propose a rule in state `draft`; user confirmation promotes to `active`; contradicted rules become `superseded`; keep rollback history. Reflexion-style: write a short verbal lesson, not weights. [Reflexion](https://arxiv.org/abs/2303.11366v4), [AgentRecall lifecycle via summary](https://skills.cat/skills/igorganapolsky/thumbgate/agent-memory), [MemToolAgent](https://www.alphaxiv.org/abs/2606.07909)
- Manual overrides by the user are hard constraints that outrank learned rules. [PowerLens](https://arxiv.org/pdf/2603.19584)
- Context pack: at job start retrieve top ~10-15 active rules (global + client + format), render as <= 40 lines; include the 3 most recent corrections for that client. Never load the whole graph.
